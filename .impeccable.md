## Design Context

### Users
Primary users are anime fans planning a seichi junrei trip, plus travelers who are already near a station or neighborhood and want to decide whether a detour is worthwhile.

The product supports users in Chinese, Japanese, and English. Their core jobs are:
- discover meaningful scenes from a specific anime
- understand what is worth visiting nearby right now
- turn selected scenes into a realistic half-day or one-day route

### Brand Personality
The interface should feel like a high-quality travel planning tool with warmth, not a generic AI chat app or a cold SaaS dashboard.

Working personality:
- clean (Wanderlog-inspired structure and clarity)
- warm (リズと青い鳥-inspired light blue palette with depth)
- practical (map-first, content-driven, photos speak)

The emotional goal is to reduce blank-page anxiety and replace it with momentum: users should feel oriented, inspired, and ready to go out.

### Aesthetic Direction

**Light blue palette inspired by リズと青い鳥 (Liz and the Blue Bird)** — clean, transparent, airy. UI stays quiet so photos and map do the visual work. Single brand color (light blue) used sparingly for interactive elements.

**Color tokens (WCAG AA verified):**
```
--color-bg:           #f8fafe   oklch(98% 0.004 240)   near-white, barely blue
--color-surface:      #edf3fb   oklch(95% 0.008 240)   hero/section backgrounds
--color-card:         #ffffff                           floating white cards + shadow
--color-fg:           #1e2a3a   oklch(20% 0.020 240)   primary text
--color-fg-secondary: #3d5068   oklch(37% 0.020 240)   secondary text
--color-muted-fg:     #47596e   oklch(45% 0.020 240)   muted text (WCAG 4.5:1 on bg)
--color-border:       #b8cbdd   oklch(78% 0.015 240)   decorative borders (cards)
--color-border-input: #6884a0   oklch(56% 0.020 240)   interactive borders (WCAG 3.0:1)
--color-primary:      #7aade4   oklch(72% 0.100 240)   light blue — buttons, badges, active
--color-primary-deep: #4d7fb8   oklch(46% 0.100 240)   EP badge bg (white text passes)
--color-primary-soft: #e6f0fb   oklch(95% 0.020 240)   CTA card background
--color-primary-fg:   #1a3660   oklch(25% 0.040 240)   dark text on light blue buttons
--color-muted:        #dce6f0   oklch(90% 0.010 240)   disabled/skeleton states
```

**Button/CTA pattern:** Light blue background + dark text (not white text on dark blue). Only EP badges use white text on deeper blue.

**Typography:**
- Display font: Noto Serif JP (clean Japanese serif, better CJK rendering)
- Body font: Noto Sans JP (clean sans, consistent CJK)
- Type scale: Perfect Fourth 1.333 ratio — 12/14/16/18/24/28/42/72

**Header:** White background, nav links (ガイド/マップ/ルート), filled light-blue Login button with dark text. Breadcrumb navigation on inner pages.

**Cards:** Pure white with subtle shadow, decorative border (#b8cbdd). Hover: translateY(-2px) + stronger shadow.

**Photography and map provide all color richness.** UI is monochrome blue-gray + one light blue accent. No second accent color needed.

Avoid: deep/dark blue fills (too heavy), gradient backgrounds (decorative), amber/coral/green accents (unnecessary), generic SaaS purple, AI chat aesthetics.

### Technical Context

Stack: Next.js 16 (SSR via @opennextjs/cloudflare), Tailwind v4, base-ui + shadcn/ui, Mapbox GL + react-map-gl, Supabase auth.
Build: SSR on Cloudflare Workers (migrated from static export).
Components: ~60 total, shared spot components (SpotCard, SpotGroup, Filmstrip, GroupToggle).
Generative UI: registry-based (`registry.ts`) mapping backend intents to visual components.
i18n: ja/zh/en, dictionary-based dynamic imports.

### Layout Direction

**Map-first layout** — the interface centers on geographic data, not chat.

- **Landing** (`/`): Left-text hero + right comparison image, anime gallery grid
- **Guide** (`/anime/[id]`): Cover + title hero → filmstrip → map → CTA → episode/area grouped spots
- **AppShell** (`/chat`): ResultPanel full width (map + spot grid), ChatPopup as floating assistant
- **Mobile** (<768px): single column, chat panel when no results, result panel when results exist

Chat is a floating popup assistant for route planning, NOT the primary interface.

**Shared components:** SharedHeader, SharedFooter, SpotCard (browse/select modes), SpotGroup (collapsible, with thumbnail preview), Filmstrip, GroupToggle (episode/area).

**Smart grouping:** TV series → by episode. Movies → by geographic area. User can toggle.

### Accessibility

- WCAG AA target — all text/background pairs verified
- Touch targets: 44px minimum
- Reduced motion: `prefers-reduced-motion` respected
- Outdoor use: sufficient contrast for bright-screen readability
- Focus visible: 2px primary outline with offset
- Two border tokens: decorative (78%) and interactive (56%, passes 3.0:1)
- Button pattern: dark text on light blue (not white on dark blue)

### Design Principles
1. UI stays quiet — let photos and map do the visual work.
2. One blue, used sparingly. Photos provide all color richness.
3. Start from user intent, not from an empty chat box.
4. Keep scenes, map, and route in the same working context.
5. Treat AI as a route copilot, not the product's main screen.
6. Make the next action obvious on every screen.
7. Every screen size gets a considered experience, not a breakpoint hack.
