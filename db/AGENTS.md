# db — AGENTS.md

Atlas versioned migrations for the shared Neon catalog/user data plane. Authentication-only legacy
migrations remain under `supabase/migrations/`. Root guide: `../AGENTS.md`.

## Commands (from repo root)

- After **any** migration edit: `atlas migrate hash --dir file://db/migrations`.
- Deploy uses `atlas migrate apply --dir "file://db/migrations" --url "$NEON_DATABASE_URL" --revisions-schema public`
  before Pulumi/Worker rollout; seed/reference data rides migrations too.

## Conventions

- Migrations are timestamped, append-only history. Add a new migration; never rewrite one already
  applied to a shared environment.
- Keep `db/migrations/atlas.sum` generated by Atlas. Never hand-edit it.
- Use Neon for catalog/user schema. Do not add data-plane tables to `supabase/migrations/`.

## Key files + entrypoints

- `migrations/*.sql` — ordered schema and data migrations.
- `migrations/atlas.sum` — Atlas integrity manifest.
- `../.github/workflows/_deploy-component.yml` — deploy-time apply gate.
- `../docs/data-sources.md` — gazetteer provenance and regeneration inputs.

## Pitfalls

- `migrations/20260714000002_gazetteer_data.sql` is a header-declared **GENERATED ARTIFACT** and
  is exempt from the 300-line rule. Never edit it by hand.
- Regenerate it and the audit CSV from repo root, then rerun the Atlas hash command:
  `node --import tsx workers/catalog/scripts/build-gazetteer.ts --stations data/raw/N02-23_Station.geojson --cities data/raw/cities500.txt --out-sql db/migrations/20260714000002_gazetteer_data.sql --out-audit workers/catalog/data/gazetteer-audit.csv`.
- The generator verifies pinned source SHA256 values in
  `workers/catalog/data/gazetteer-sources.json`; `--update-sources` is for deliberate source-lock
  review, never a bypass for accepting unexplained drift.
