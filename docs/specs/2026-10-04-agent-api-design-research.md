## 1 Anthropic 自家怎么做

**Managed Agents**（beta 头 managed-agents-2026-04-01）。资源：Agent（版本化，session 绑 latest 或 pin 版本）/Environment/Session/Events；状态 idle/running/rescheduling/terminated，做完是 idle；【推断】普通 session 无 run 资源，只有定时部署的 deployment_run（https://platform.claude.com/docs/en/managed-agents/sessions；/session-operations）。流式：一切是 `{domain}.{action}` 事件（`user.*/agent.*/session.*/span.*`）；`GET /v1/sessions/{id}/events/stream` 只送打开后的事件、无 resume cursor，重连 = 列历史再 tail、按 event id 去重；token 预览 stream-only，持久化的 agent.message 才是记录（/events-and-streaming）。结果：无单一 result 对象，`session.status_idle` 带 stop_reason end_turn/requires_action/retries_exhausted/budget_reached/refusal；文件经 Files API 按 session 取；outcome = rubric + 独立 grader；无 JSON Schema 输出参数（https://platform.claude.com/docs/en/api/beta/sessions/events/list；/managed-agents/define-outcomes）。工具：自定义工具 = agent.custom_tool_use → idle(requires_action) → user.custom_tool_result；服务端工具策略 always_allow/always_ask/auto，审批 user.tool_confirmation；无客户端 hook API（/permission-policies；/migration）。身份：API key + 版本头；凭据入 workspace 级 vault、按 session 以 vault_ids 挂——"产品在 agent 粒度管、用户在 session 粒度管"；create 无 user_id 参数（/vaults）。usage：session 累计 usage 含 list_cost（美分字串、公开价）；budget 是硬上限，到顶转 idle(budget_reached) 不失败；【建议】用 budget 别轮询自停（/budgets）。可观测：事件历史全量可拉、Console session viewer、`span.model_request_*` 带 model_usage；无 OTel 导出、无反馈端点（§8）。webhook 只送 type+id 要你 GET，可重复、无序，按 event.id 去重（/webhooks）。

**Messages API**（anthropic-version 2023-06-01）。无状态送全史；客户端工具循环 `while stop_reason==tool_use`，服务端工具请求内循环、到上限 pause_turn（https://platform.claude.com/docs/en/agents-and-tools/tool-use/how-tool-use-works）。SSE 命名事件，未知类型必须容忍，200 后仍可能 error 事件（/build-with-claude/streaming；/api/errors）。结构化：output_config.format 约束解码 + strict 工具（/build-with-claude/structured-outputs）。★鉴权首选 Authorization: Bearer（API key 或 WIF 短期 token），x-api-key 为遗留；多 workspace key 必带 anthropic-workspace-id（/api/overview）。★终端用户归因两条：metadata.user_id（opaque）与 beta 的 anthropic-user-profile-id 头 + User Profiles API（/api/messages/create）。日期版本头，枚举输出（含流事件类型）可加变体不升版；每响应 request-id（/api/versioning；/api/errors）。无幂等键，SDK 的 idempotencyKey 已 deprecated 无效（§8）。Batches：custom_id、轮询、JSONL 无序、半价（/build-with-claude/batch-processing）。

**示例与博客**。customer-support-agent：无状态 `POST /api/chat {messages, model, knowledgeBaseId}`，客户端重发全史，结果靠提示词要 JSON + Zod 校验，RAG 来源放 x-rag-sources 头；★500 返部分同形 JSON，但自带 UI 对非 2xx 直接 throw 不渲染（https://raw.githubusercontent.com/anthropics/anthropic-quickstarts/main/customer-support-agent/app/api/chat/route.ts，目录最后提交 2025-10-15）。financial-data-analyst：tool_use 的 input 就是结果，不回传 tool_result（同仓 financial-data-analyst/app/api/finance/route.ts）。managed-agents/slack：session metadata 是唯一路由状态、无数据库；mcp-server-typescript：9 个工具包 Sessions API，wait_for_idle 把 SSE 变同步调用（同仓 managed-agents/*/README.md，2026-09）。【建议】区分 workflow 与 agent、从最简起步（https://www.anthropic.com/engineering/building-effective-agents，2024-12-19，页面现挂横幅指向 Managed Agents）。【建议】多步操作合成少量有目的工具（schedule_event 而非 list_users+list_events+create_event）、返回高信号字段、给 response_format 枚举、截断分页、错误可行动（https://www.anthropic.com/engineering/writing-tools-for-agents，2025-09-11）。【建议】transcript 是评测记录；评产出不评路径；每 trial 干净环境；20–50 个真实失败任务起步（https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents，2026-01-09）。Managed Agents 博文：agent = session（append-only 日志）+ harness + sandbox，harness 调的是 execute/wake/getSession 这类接口（博文未说是否公开，调研者注）；凭据不进 sandbox，经 proxy 取 vault（https://www.anthropic.com/engineering/managed-agents，2026-04-08）。

## 3 成熟垂直产品怎么做（◆ = 同时有聊天 agent 与底层能力 API）

**Devin v3 ◆**。/v3/organizations/{org}/sessions 为中心，messages/attachments/tags/insights 挂其下，parent_session_id 可嵌套；create 只必填 prompt，follow-up 自动唤醒 suspended；无流式、无出站 webhook，官方流程轮询 messages；状态 new…suspended/resuming + status_detail（working/waiting_for_user/waiting_for_approval/finished）；create 传 JSON Schema（Draft 7，64KB），agent 必调 provide_structured_output 后以 structured_output 返回；service user key 与个人 token 同为 cog_，create_as_user_id 代人建 session 但审计归 service user（【建议】长期自动化用 service user）；acus_consumed、max_acu_limit、日消耗端点；错误 RFC 9457。关系：UI/Slack/API 的 session 是同一资源、origin 字段区分；【推断】web app 是否调公开 v3 文档未说；另有托管 MCP server（https://docs.devin.ai/api-reference/v3/sessions/post-organizations-sessions；https://docs.devin.ai/api-reference/authentication；.../common-flows；https://docs.devin.ai/work-with-devin/devin-mcp）。

## 5 对照我们

- 聊天形状 + AI SDK UI 流：符合。协议现成，Cloudflare 聊天 agent 与 Browserbase 转录都用它（ai-sdk.dev stream-protocol；developers.cloudflare.com chat-agents；docs.browserbase.com how-it-works）。流里以 transient 的 `data-usage` part 送会话累计 usage（`workers/edge/src/agent/views/event-chunks.ts:19`），这是协议允许的自定义 transient data part；协议自己给 usage 留的位置是 finish 回调与 messageMetadata（★ai-sdk.dev message-metadata）。没有消费者读它。
- 服务端 session + 一会话一 turn 的 409 turn_in_flight：服务端 session 合多数；409 拒绝是被接受的少数（Cursor 409 agent_busy、LangGraph reject），多数是 enqueue/steer（LangGraph 默认 enqueue、OpenAI Agents API steer、Copilot SDK steer/enqueue、Cloudflare messageConcurrency）。
- 单轮 100 秒预算、无 webhook、无按 run id 的 GET：部分偏离。turn 已是耐久 run：202 返回 `run_id`/`operation_id`（`workers/edge/src/gateway/native-admission-response.ts:8-9`），`GET /v1/conversations/{id}/stream?operation_id=` 可重连且不再提交（`workers/edge/src/gateway/native-stream.ts:10-12`），历史路由给出 run 状态含 `deadline_exceeded`（`packages/contract/src/session-history-contract.ts:56-63`）。缺的是 100 秒之外的续跑（`workers/edge/src/agent/host/turn-deadline.ts:13`）、按 run 的 JSON 状态或结果读取（历史只报最近一次 run，`workers/edge/src/agent/views/history.ts:49-52`；stream GET 返回的是 SSE）和 webhook。正常的 POST 以 200 流式返回并带 `x-operation-id` 头（`workers/edge/src/agent/views/watch-response.ts:81`）；202 是未流式的 pending 情形。可比的同步上限只有 Salesforce 120 秒；其余有耐久 handle 加轮询或 webhook（表第 3 行）。SD-12 计划中的 plan_pilgrimage 在仓库里尚无此工具（现有的是 `plan_route`），若超 100 秒只能失败。
- x-turn-id：已定义并有测试的按提交幂等键：同键同摘要重放原 turn（200/202，同一条 wire），同键不同摘要为内部 conflict、线上同样答 409 turn_in_flight（`workers/edge/src/gateway/native-admission-response.ts:11`），`(sessionId, clientMessageId)` 唯一约束（`workers/edge/src/gateway/native-submission.ts:57-61`；`workers/edge/src/agent/admission/request-intent.ts:7-17`；`packages/pi-session-neon/src/contract.prisma:78`；模型 turn 的重放与冲突见 `workers/edge/admission-test/admit.test.ts:41-43,54-55` 与 `workers/edge/host-integration-test/reconnect-during-drive.test.ts:14-37`）。与 OpenAI/Workspace 的"重放返原结果"同派。偏离只在：这套语义没有写进 `packages/contract` 和公开文档。
- 历史路由省略工具结果与 `data-response` 的 data（`packages/contract/src/session-history-contract.ts:23-31,84-89`；`workers/edge/src/agent/views/history.ts:62-66`），但重连走的是 stream GET，它重放工具输出和完整 `data-response`（`workers/edge/src/agent/views/event-chunks.ts:27-33,48`；`workers/edge/host-integration-test/native-stream.test.ts:35`）。Notion 是"省略工具输入输出"的先例，但回复本体仍可从 agent.message 读到（developers.notion.com quickstart.md；query-session-events.md）。偏离只在历史路由：审计和评测从历史拿不到结构化答案，脱离"saved items 即记录"一派（OpenAI Agents API events.md；ChatKit thread-stream-events.md）。
- 不暴露 model id/provider/per-call usage：部分偏离。会话累计 token 与 cost 已随流送出（上文 `data-usage`）；model id 与 provider 在任何 part、头或历史形状里都没有，也没有逐次调用的 usage。多数在 run/session 上给 usage（表第 8 行）；model 暴露不一（Claude Code system/init 报 model，AG-UI metadata 可选带 model 名）。
- 身份只有人类 JWT + 匿名 Turnstile、无机器/委托身份：偏离。调研到的对外 agent/能力 API 都有机器身份（Devin service user、Cursor service-account key、Jules key、Stripe Agent key、MCP OAuth 2.1 + RFC 8707），唯一反例是 GitHub agent tasks 只收用户 token。计划中的 MCP 客户端与 Claude Skill 必触发此项；MCP 授权规范是 MCP 面的直接依据，与方案的 issuer registry/principal kinds 同向（表第 9 行）。
- 无应用 span；日志按规则不含 id：偏离在 span。Workers Traces 已开（`workers/edge/wrangler.toml:237-240`，全采样），但 `workers/edge/src` 与 `packages/agent/src` 没有任何自定义 span；网关请求日志只记路由类、方法、状态、时长，并有意不记路径和 id（`workers/edge/src/gateway/request.ts:46-48`）；两条鉴权失败日志是例外，记了原始路径（`workers/edge/src/gateway/responses.ts:38-40,61-63`）。所有实现以 session id 关联（Agent SDK span session.id、AgentCore span session.id、Cloudflare/OTel gen_ai.conversation.id）；request-id 头是 Anthropic/Manus 的最低做法。按 session 关联的自定义 span 加 OTLP 导出是共识方向；"release 属性"无来源直接规定，但 agent 版本可 pin/可查是共识（表第 10 行）【推断】。
- 评测 SUT = agent：合 Anthropic（评产出不评路径、每 trial 干净环境，demystifying-evals 2026-01-09）；ADK 同时评 trajectory（adk.dev/evaluate），来源有分歧。"评测 catalog 源指向 staging 基础 API + service credential"：证据薄——只有 Sierra（2024-06-03）明说对 mock API 仿真，Anthropic 的"干净环境"更偏 replay/mock；没有来源支持或反对 staging 方案【推断】。

**两层拆分是否 best practice**【推断，依据如下】。拆成部件看各有共识支撑：无状态能力端点（MCP 2026-07-28 去 session、Cloudflare McpAgent 转无状态 handler）、每 principal 鉴权限流（表第 9 行）、按 session 关联的 trace（表第 11 行）、能力与会话端点并列于一套 API（Intercom）。但整体命题"自家聊天 agent 是自家公开能力 API 的一个消费者"，没有找到任何成熟产品的明确表述。最接近的四个样本各差一层：Codex app-server 驱动 VS Code 扩展——第一方 UI 消费公开 agent 接口，我们的 web app 消费 /v1/chat 已属此类，不涉及能力层（learn.chatgpt.com/docs/app-server.md）；Notion 托管 MCP 是公开 Notion API 的客户——它是工具服务器不是聊天 agent，Agent APIs 对话的 Custom Agents 是否走公开 API 未说（developers.notion.com/guides/mcp/overview.md）；Browserbase Agents 叠在 Sessions/Functions/Search/Fetch 之上、底层可单独调用——未说 agent 走公开契约（docs.browserbase.com how-it-works）；Intercom 能力端点与会话端点并列——关系未说。更常见的表述是反方向：一个 harness 多个表面（Cursor、Factory、Copilot、Devin origin）；Anthropic 自己的 Managed Agents 博文写的是 harness 调 execute/wake/getSession 这类接口，博文未说它们是否公开（anthropic.com/engineering/managed-agents）。反例：Shopify Sidekick 不走公开 MCP、Ada 原生渠道不开放 API、Zendesk API 与 Messaging 互斥。结论：两层拆分"部件有据、整体无先例"。收益：无后门可由契约与测试强制，MCP/Skill 与 agent 共用一条鉴权/限流/trace 路径。代价：agent 调自己 API 的二次鉴权与限流；Workers 内从 service binding 改走 HTTP 契约客户端的序列化开销；工具仍须按 Anthropic 建议合并而非 1:1 映射端点；评测依赖 staging 可用性。

## 6 可选方向

四个方向不排序，不含推荐。

A. 能力端点并列、不改 agent 路径（Intercom 式）：/v1 加 task 型 resolve_anime/search_points/plan_pilgrimage 与 /v1/chat 并列，共享 oRPC 契约类型，agent 继续经 service binding 调 catalog。依据：Intercom fin-agent-api、LangGraph 无状态/有状态 run 并存、Anthropic Messages+Managed Agents 并存。代价：两条到 catalog 的路径，"无后门"只对 web app 成立；契约漂移靠测试兜底。

B. 完整两层拆分（方案原样）：agent 经契约客户端调 /v1/catalog/*，issuer registry 三种 principal，Workers Traces + OTLP。依据：MCP 2026-07-28 无状态 + OAuth 2.1 audience、Cloudflare 无状态 handler、表第 9/11 行。代价：见 §5；无成熟产品先例可引。

C. 一个契约、两种绑定：能力层为内部模块，对外以同一 oRPC/OpenAPI 契约给 MCP/Skill，agent 在进程内/service binding 调同一模块，但强制同样的 principal 与 trace 上下文传播（MCP 已把 traceparent 放 _meta；AgentCore Gateway 把 API 变 MCP 工具）。依据：Cursor/Factory/Copilot"一个 harness 多表面"、MCP changelog、AgentCore gateway.md。代价："无后门"靠契约测试与 lint 保证，非运行时保证；两种绑定的鉴权语义要对齐。

D. 独立于拆分的三项共识缺口：自定义 span 带 session id 并经 OTLP 导出（网关请求日志按现行规则不记 id）；把 x-turn-id 已实现的重放语义写进契约与公开文档；为超 100 秒的规划类任务加后台续跑（按 run 的 JSON 状态读取，webhook 可后置）。依据：表第 3/6/11 行。代价：Durable Object 续跑与告警、按 run 的读模型、webhook 签名各是独立工作量。

## 7 需要 owner 拍板

1. 机器/委托身份回不回来（AUTH-1 #945 删过 API key）：MCP 规范的 OAuth 2.1 资源服务器 + audience 绑定、Devin/Cursor 式 service key，还是 GitHub 式只收用户 token。
2. "无私有后门"的约束范围：只约束 web app（现状、A、C），还是也约束 agent（B）。
3. 历史路由是否补回工具结果与 `data-response` 的 data（重连路径已有），或维持 Notion 式脱敏。
4. 是否在 run/历史上暴露 model id 与逐次调用 usage（会话累计 usage 已在流里；多数在 run/session 上给 usage，model 做法不一）。
5. x-turn-id 的重放语义已实现（同键同摘要重放原 turn、不同摘要答 409 turn_in_flight）：是否写进契约与公开文档并作为承诺保持。
6. 是否要 100 秒之外的后台续跑、按 run 的 JSON 状态读取与 webhook；若要 webhook，送 id（Anthropic 薄）还是全量（A2A 厚）。
7. 评测 catalog 源：live staging + service credential，还是 record/replay/mock（Sierra、Anthropic 干净环境）。
8. /v1 版本策略与弃用窗口：日期头、URL 大版本或 beta 头；12 个月是三处出现的窗口。
