## 4. Traps that cost time here

The ones on #1840 are not repeated. These are the rest.

**A PR title that fails `commitlint` could not be fixed by editing it.** The job read
`github.event.pull_request.title`, the workflow did not listen for `edited`, and a rerun replays the
payload — so after shortening a 73-character title the job reported `current length is 73` again, in
text byte-identical to the first failure. Only `gh pr close` + `gh pr reopen` produced a fresh
verdict. **Fixed in #1862**: the title is now read through the API at run time.

**A shell double-quoted string executed a comment's code spans.** An issue comment was posted with
`--body "…"` instead of a quoted heredoc; markdown code spans are backticks, and inside double
quotes a backtick is command substitution. `` `workers/edge/package.json` `` ran as a command and its
error output replaced the prose. `gh` returned a URL and the shell's errors went to stderr, so
**nothing on the success path said the body had been rewritten**. Every issue or PR body goes through
`<<'EOF'`, and gets read back after posting.

**A writer wiped the launcher's receipts.** Briefs told writers to write their report to the
launcher's own state directory, so one treated it as a workspace and its cleanup took
`launch.json` and `dispatch.json` with it; `orca-headless cleanup` then refused. Report paths now
point at a sibling directory the launcher does not own.

**`cleanup` has never closed a terminal in this run.** All 100 workers read `terminalState: retained`,
including every one where `cleanup` returned `{"status":"cleaned"}`. Orca's accounting is
`dispatchStatus`; a cleanup failure is not outstanding work and should not be reported as such.

**After a rebase, "the card still works" and "the reviewed scope survived" are different claims.**
`git diff <old> <new>` compares two *bases* and is useless for this. The cheap check is
`git diff <commit>^..<commit> | git hash-object --stdin` before and after — equal hashes mean the
patch is byte-identical.

**A diff hunk's line order is not the file's structure.** An `if:` condition appearing directly under
one step's `run:` in a hunk belonged to the next step in the file; reading the hunk alone produced a
false finding about a lint being disabled.
