# Seichijunrei 用户旅程 — 完整设计指南

> 给设计 agent / 设计师:这份文档讲清楚**这个产品是什么、用户从哪来到哪去、每一屏要解决什么**。
> 你用 動森キャンプ 设计系统的组件去搭这些屏时,先读这里——它告诉你每个屏的「处境、情绪、要放什么、对应哪张已画的 mockup」。
>
> 定案于 2026-06-12(/office-hours 两轮评审 9/10),配套 mockup 在 `chat-mockups-2026-06-12/`。

---

## 0. 一句话定位

**Seichijunrei = 动漫圣地巡礼的「现场作战系统」。**

不是泛用 AI 旅行规划器。它针对一个具体的文化行为——动漫迷专程去动画取景地(聖地)、对照截图找机位、打卡、发帖——做全链条工具。**核心价值在现场(走的那一刻),不在规划。**

主打记忆点:**「一句话 → 一张能直接出发的时刻表」**。用户说「想去《吹响吧!上低音号》的宇治,半天」,产品给出站粒度、带 HH:MM 精确时刻、散步段独立可见的海报级路线卡,然后一路陪他走完、帮他发帖。

## 1. 产品形状:环,不是漏斗

这是理解整个产品最重要的一件事。**获客引擎在产出侧,不在消费侧。**

传统旅游产品是漏斗:买广告/SEO 把人灌进顶部,转化、流失。Seichijunrei 是**环**:每个走完巡礼的用户产出一个「分享物」(一张 9:16 竖图しおり + 一条免登录公开页),这个分享物回流到社交渠道,变成下一个人的入口。

```
小红书帖子 / X 卡片 / Google 长尾 / 朋友直发
   ↓ 点进来
免登录公开路线页 /share/:routeId(自带「✓ 有人走过」痕迹)
   ↓ 「自分用にアレンジ」
chat 改装车间(引用别人的路线为底,一句话改)
   ↓ 路线卡 → 保存(★ 登录墙立在这一刻)
我的路线 → 出发前夜 → 歩くモード(审判时刻)
   ↓ 走完
完成屏 → しおり 9:16 竖图
   ↓ 发帖
小红书(图直接入相册) / X(链接卡带 OG 图)
   ↓ 变成下一个人的入口 —— 环闭合
```

**任何一段断裂,环就转不起来。** 设计每一屏时都问:这一屏是在帮环往前转,还是卡住它?

### 两个 persona(两条渠道)

- **中文小红书圈**:刷到帖子 → 评论区点链接 → 免登录落地 → 改装路线。**小红书对外链有敌意**,所以**图片导出不可省**——必须能生成可直接保存进相册的竖图,不能只给链接。
- **日本 X 圈**:X 吃链接卡片(OG 图自动展开)→ 点卡片 → 免登录落地。

两个 persona 进来都落同一个资产:**免登录公开页**。

### 这个产品的「家」是路线,不是会话列表

Route(路线)是核心对象,有五个视图,设计时要意识到同一条路线会以这些形态出现:

1. **chat 里的路线卡**(规划时)
2. **地图上的轨迹 + 常驻的金色「路线 pill」**(索引)
3. **`/routes/:id` 详情页**(路线的家,扫码落地点;随旅程变形:预习版 → 现场入口 → 纪念版)
4. **`/routes/:id/walk`**(现场 Walk Mode)
5. **`/share/:routeId`**(对外只读版,免登录,带 ✓ 痕迹)

## 2. 巡礼之环:5 段 18 断点全景

旅程被切成 5 段、18 个断点(J1–J18)。每张开发卡都该声明「我修的是 J 几」。下表是骨架,§3 起逐屏详解。

| 段 | 断点 | 这一刻用户在干嘛 | 现状 | 影响 |
|---|---|---|---|---|
| **発見 Discover** | J1 分享物缺失 | 在小红书/X 刷到,想点进来 | 弱(无产出物) | 高·环断 |
| | J2 落地即登录墙 | 点外链进来 | 弱(重定向 /login) | 高·环断 |
| | J3 无作品浏览面 | 想看「别人在巡礼什么」 | 弱 | 中 |
| **判断 Decide** | J4 guide 页缺失 | 想看某作「有多少圣地、值得专程吗」 | 弱(页面已删) | 高 |
| | J5 判断素材未成页 | 评估圈分布、代表帧、规模 | 弱 | 中 |
| **計画 Plan ★** | J6 无流式反馈 | 发消息等 agent 响应 | spec 完未实现 | 高 |
| | J7 登录边界 | 用 chat 规划,纠结要不要登录 | 未决 | 中 |
| | J8 效率回归 | 再访、快速重提、用历史 | 缺 | 低 |
| **歩く Walk ☆审判** | J9 无现场视图 | 站在圣地附近,我在哪/下一站/还剩多久 | 零实现 | **最高** |
| | J10 机位对照 | 对照动画截图找正确机位 | 零 | 高 |
| | J11 附近还有什么 | 看附近有没有其他作品点位 | 后端有·缺 UI | 中 |
| | J12 导航深链 | 不确定怎么走,要精确导航 | 缺 | 高·成本极低 |
| | J13 完成感/打卡 | 「我来了」,记录进度 | 零 | 中 |
| | J14 现场环境约束 | 户外强光/弱网/单手 | 零 | 中(贯穿) |
| **残す Keep** | J15 分享物(产出) | 走完想发帖 | 萌芽 | 高 |
| | J16 同行只读/协作 | 结伴想同步打卡 | 缺 | 中 |
| | J17 历史路线 | 数月后查「上次走哪了」 | 缺 | 中 |
| | J18 打卡照×对照帧合成 | 生成自己的对比图 | 缺 | 低·远期 |

**审判时刻 = J9–J14(Walk)。** 创始人本人实证:站在宇治站前,他弃用了自己的产品,改用「四件套」——Google Maps 导航 + 相册里的动画截图 + Anitabi 网页 + 小红书攻略。**这一段的产品使命就是:用一个 app 正面打败这四件套。** 失败 = 用户切回四件套 = 产品失去存在意义。所以 Walk 是设计优先级最高的地方,§3.4 给它最多篇幅。

## 3. 逐屏详解

### 3.1 段 — 発見 Discover(入口屏,现状弱)

环的入口。两类访客:刷到分享物的、看完番想了解圣地的。两类都要在**免登录**前提下被接住。

#### 屏 · 公开分享页 `/share/:routeId`(J1/J2 解,环的主入口)
- **用户处境**:在小红书刷到一张竖图,评论区点了链接进来。情绪:好奇 + 半信半疑(「这路线靠谱吗」)。
- **这一屏要干的事**:用「别人真走过」的信任,把好奇转成「我也想走」。
- **放什么**:
  - 右上角「ログイン不要」标注(免登录是卖点,要明示)。
  - **「✓ 作者已走完」绿色徽章** + 每站名后的 ✓ 痕迹——这是核心信任来源。
  - **动画帧 × 作者实拍** 双图并列(pair grid):左动画截图、右作者现场照,证明「这个机位真能拍出来」。
  - 站粒度的路线概览(复用路线卡组件的只读形态)。
  - 两个 CTA:**「この路線を自分用にアレンジ」**(金色,主)→ 进 chat 引用态(A2b);**「この作品の聖地をすべて見る」**(cream)→ 进作品公开页。
- **设计赌注**:落地物是「别人走过的一条路线」(自带 ✓ 信任),不是「作品全景」。先给具体的、被验证过的东西。
- **对应 mockup**:`journey-flow.html` 屏②。

#### 屏 · 作品公开页 `/anime/:id`(J3/J4/J5 解)
- **用户处境**:看完一部番,想知道「它的圣地有多少、分布在哪、值不值得专程去一趟」。
- **放什么**:
  - **名場面 TOP**(按截图数排序,如「大吉山 18 カット / 北宇治高校 14 カット」)。
  - **圣地圈分布地图**(static):只画圈泡(teal 圆,面积 ∝ 件数,白字数量徽章),**永不在低 zoom 画 >50 个 pin**。
  - 示例路线预览(别人已走的路线卡缩略)。
  - CTA:**「AI にルートを組んでもらう」** → 进 chat。
- **数据**:总圣地数(如 228 件)、圈分布、代表帧。
- **设计要点**:这是「判断值不值得专程」的页面,要让规模感和代表画面一眼可见。

### 3.3 段 — 計画 Plan(chat,★ 已 spec 完整)

这是产品的功能核心:**一句话 → 能出发的时刻表**。chat 不是一个聊天框,它是一台「把模糊意图变成精确路线」的机器,过程要让用户**看得见**(「看着它一步步找出圣地」)。

chat 页采用**双形态分期**:
- **Phase 1 / V3 单列流**(全端,也是移动端最终形态):整页一条对话流,generative UI 卡片(点位卡、地图卡、路线卡)直接落在流里。心智最简,移动端零降级。**先做这个。**
- **Phase 2 / V1 双栏工作台**(桌面 ≥1024px,后置到环闭合后):左对话退为旁白、右栏是海报级路线卡 + 地图的「活文档」。
- **V2(map-first + 狐狸浮窗)已淘汰**——那是 Anitabi 的产品基因,长回复在浮窗里憋屈。但「狐狸第一人称叙述过程」这个记忆点,作为遗产保留注入 V3/V1。

> chat 有一套完整的状态机(进入方式 A、回合等待 B、内容形态 C、异常 D、交互 E、选点 SP、输入区 G)。§5 是完整状态表,这里先讲主线情绪。

#### 主线:一个回合的情绪曲线
1. **发送(B1)**:用户气泡乐观渲染(nook-teal tile,右对齐),输入框立即清空,发送键播放按压动画(下移 4px,影消失)。
2. **<1s(B2a)**:只出狐狸 typing 指示(头像 + 三点跳动)。**短回合不值得仪式感,不出管线。**
3. **1–4s(B2b)**:升级为**管线/足迹卡**,步骤逐个点亮——`タイトル確認·Bangumi ✓ → 聖地を検索·Anitabi 进行中(shimmer) → ルートを作成 等待`。每步带**数据源徽章**(Bangumi/Anitabi 的 muted pill)。狐狸第一人称副标题:「いま Anitabi でさがしてるよ… 8/23」。
4. **≥4s(B2c)**:管线下追加**作品情绪卡**——该作台词 + 场景帧渐变底 + 白字。例:「上手くなりたいって、思ったんです。本気の本気で」— 高坂麗奈 · 第8話。把等待变成沉浸。
5. **结果落位(B3→B4)**:generative 卡片逐个 `.entrance-up` 落位;管线折叠成**足迹一行**:「✓ タイトル確認 → 23スポット → ルート作成 **9.2s** · 詳細を見る ▾」;出追问 chips(nook 三色 tile)+ 👍👎。

**关键原则:纯文字回合永不出 skeleton/管线**(打招呼、答疑这种 B2a 直达 B4)。只有视觉工具(搜索/排路线)开跑才插入卡片 skeleton。**没经过 agent 的事,就不演 agent 的戏。**

#### 核心产物:路线卡(TimedItinerary)
这是整个产品的招牌资产,海报级,V1/V3 共享同一组件(只是挂载点不同):
- **卡头**:英文眉标(`UJI · HALF-DAY ROUTE`)+ 日文卡名(「宇治・半日きらめきルート」,Nunito 900)+ meta 行(pacing「ゆったり」绿 pill / 「6 スポット」/ 「徒歩 60 分 · 3.8 km」/ 「13:00 → 16:35」)。
- **时间轴(站粒度)**:三列 grid `HH:MM | 轨道点线 | 站点内容`。起点 teal 实心圆、高光站金色 ★ 圆(「大吉山展望台 ★」)、终点金色圆。
- **散步段独立可见**(绿色 walk 胶囊):`🚶 6分 · 平等院表参道、第2話に登場`——走路本身也是巡礼的一部分,要可见。
- 每站:站名 + 话数 tag(nook-yellow)+ 停留时长 + **场景帧缩略图**(含话数时间戳「第8話 18:30 のカット」)。
- **卡底 CTA**:「しおりにして共有」(金色,主)/「Google マップで開く」(cream)/「保存する」(cream)/「歩くモード」预留位。
- **对应 mockup**:`v3-stream.html`(紧凑版)、`v1-workbench.html` ACT 3(两列海报版)。

#### 登录墙(J7,P5 裁决)
**看/改/排都免登录,只有按「保存する」这一刻才弹登录(magic link)。** 登录的价值主张不是「保存」,而是**「把路线带去旅途」**——桌面排好 → 扫码/同账号 → 手机走。匿名态路线暂存于匿名 session,登录后归属账号,用户不重做任何事。

### 3.4 段 — 歩く Walk(☆ 审判时刻,设计优先级最高)

**这是整个产品成败的地方。** 用户已经规划好,现在站在真实的圣地附近,手机在手。竞品(也就是创始人现场真用的)是**四件套**:Maps 导航 + 相册动画截图 + Anitabi 网页 + 小红书攻略。Walk Mode 这一屏(`/routes/:id/walk`)必须把这四件套合成一件,而且更好用。

设计这一屏的统领原则:**户外强光下、单手、可能弱网,用户每多切一次 app,我们就输一点。**

#### 屏 · 歩くモード(Walk Mode)
Citymapper 范式:**当前站置顶放大,其余站序缩小。** 自上而下:

1. **顶部进度条**:彩色格子 `●●●○○○○`,每打卡一站点亮一格。一眼看到「走了几站、还剩几站」。
2. **当前站置顶放大卡(walk-hero)**——这是屏幕主角:
   - 大字号站名(户外强光对比度:DESIGN.md A11y outdoor 条款,字号要大、色对比高)。
   - 当前站序号:「いまここ → 3/7」。
   - **场景对照帧**(scene-thumb):动画截图缩略图直接嵌在卡里,**不需要用户翻相册**。带话数时间戳「第8話 18:30 のカット」。
   - **「📷 構図をくらべる」** 按钮 → 进机位对照子视图(对照动画构图找角度)。这是 J10:用户认识的是**画面**不是地名,动画帧是钩子。
3. **当前站操作区**(屏幕下半,单手可触):
   - **「🧭 Mapsで開く」**(J12):直接深链跳出到 Apple/Google Maps。**不自建导航**(P3:导航让赢家赢,我们只做深链,成本极低但不做会被吐槽)。
   - **「✓ ここに来た!」**(J13):金色全宽大按钮,最大热点。点了 → 打卡(本地存 + 在线同步)→ 下一站自动置顶 → 进度条点亮一格。满足感的来源。
   - **「📍 近くにあと N スポット」**(J11):底部按钮 → 附近点位 sheet 滑出(替代现场开 Anitabi 网页)。
4. **下一站行**(低调,不抢当前站):「つぎ → 宇治神社 · 🚶15分 下り」。
5. **全部走完** → **完成屏**(见 3.5)。

#### 现场环境约束(J14,贯穿 Walk 全程)
- **户外强光**:大字号、高对比。这不是审美选择,是「站在太阳底下看不清就输」。
- **弱网/离线**:route bundle 预载(JSON + 帧图 + 静态地图);看缓存路线不需要在线鉴权;打卡弱网下本地排队、回网同步。离线地图用**每站静态 PNG**(不是矢量切片——iOS 50MB 上限塞不下)。
- **单手**:关键操作(打卡、Maps 深链)放屏幕下半区。
- **PWA scope 收窄**:只做「歩くモードの离线壳」(manifest + SW 缓存 route bundle + 加到主屏),**不做全 app 离线**。

#### 对应 mockup
`journey-walkthrough.html` Step 8、`journey-flow.html` 屏⑦。也可参考已经做出来的 `walk-v0/index.html` 原型(宇治 6 站,真跑通过)。

### 3.5 段 — 残す Keep(产出侧,环的回流引擎)

走完那一刻是**用户情绪的最高点,分享意愿最强**(之后每过一小时衰减)。这一段把情绪变成分享物,分享物变成下一个人的入口。

#### 屏 · 完成屏
- **狐狸举旗**(🦊🚩)图标 + 「巡礼完了!N/N」大字。
- 统计:「徒歩 N分 · N.Nkm · 13:00→16:35」。进度条全满。
- 两个 CTA:**「しおりを作る」**(金色,热点,趁情绪高)/「あとで(マイルートに保存済み)」(cream)。
- **对应 mockup**:`journey-walkthrough.html` Step 9、`journey-flow.html` 屏⑧。

#### 屏 · しおり预览 modal(J15,与 J1 同一交付物)
这是环的产出物,也是别人的入口。**竖版 9:16**(为小红书相册而生):
- 封面帧渐变底(路线代表站的动画参考帧)+ 白字标题 + 阴影:「響け!ユーフォニアム / 宇治 · 2026.07.04」。
- 打卡清单:时刻 + 站名 + ✓。
- 完成率:「巡礼完了 N/N · 徒歩 N分」。
- 导出:**「画像を保存」**(金色,→ 小红书直接入相册)/ **「リンクをコピー」**(cream,→ X/微信,链接卡自动带 OG 图)。
- 数据自动合成(打卡记录 + 路线),用户**无需手动编辑**。
- **对应 mockup**:`journey-walkthrough.html` Step 10、`journey-flow.html` 屏⑨。

#### 回流(J16/J17/J18,部分后置)
- 分享物发出 → 下一个人看到 → 点进免登录页 → 「アレンジ」→ 进 chat 引用态(A2b)→ TA 的旅程是 Step 6→10 的重放。**环闭合。**
- 历史路线 `/routes`(マイルート,J17)、同行协作(J16)、打卡照×对照帧合成(J18)后置。

## 4. 核心 Generative UI 资产清单

设计 agent 搭界面时反复会用到这几个「积木」,它们形态无关(V1/V3 共享):

| 资产 | 是什么 | 关键元素 |
|---|---|---|
| **路线卡 TimedItinerary** | 招牌产物,海报级 | 英文眉标 + 日文卡名 + pacing pill + 站粒度时间轴(HH:MM)+ walk 胶囊 + 场景缩略图 + しおり/Maps/保存 CTA |

## 5. chat 状态机完整表

chat 有四层正交状态:页面级(A)、回合级(B)、内容形态(C)、异常(D)、交互(E)、选点工作台(SP)、输入区(G)。设计任何 chat 相关屏先查这里。

### A. 页面级(怎么进来的)
- **A1 冷启动空态**:狐狸问候气泡(「こんにちは!どの作品の聖地へ?」)+ 3 枚 nook tile 示例 chips(ユーフォニアム teal / 君の名は。yellow / ぼっち pink)+ input 自动聚焦。V1 右栏:虚线框 + 🗺️ +「作品をきくと、ここに地図とルートが現れます」。
- **A2 带 query 进入**:首页搜索框提交跳转,进页即渲染用户气泡(乐观)直接进 B2,不重复打字。
- **A2b 引用路线进入**(高频!):从公开页/详情页「アレンジ」按钮进来,chat 顶部渲染「📎 引用中:〈路线名〉」上下文卡,agent 以该路线为底重组。「拿别人的路线来改」比空输入框更高频。
- **A3 恢复历史会话**:历史消息全量渲染,旧管线一律折叠成足迹行,滚动锚到底部。
- **A5 后端不可达**:顶部 error banner「サーバーに接続できません · 再試行」,input 禁用。

### B. 回合级(分级等待)
B0 composing → B1 sending(用户气泡乐观)→ **B2a <1s**(只狐狸 typing)→ **B2b 1–4s**(管线点亮 + 数据源徽章 + 狐狸副标题)→ **B2c ≥4s**(追加作品台词情绪卡)→ B2d(视觉工具开跑才插 skeleton)→ B3 streaming(打字机 + 卡片逐个落位)→ **B4 settled**(管线折叠成足迹行 + 追问 chips + 👍👎)。

### C. 五种回合内容形态(settled 渲染什么)
- **C1 greet/answer**:仅 AI 气泡,无卡无管线。
- **C2 clarify 澄清**:AI 气泡 + 2–4 个候选按钮(cream 按压,44px 高)+ 逃生口「都不是,我重新说」。例:「ユーフォ」→「響け!ユーフォニアム(TV)」/「リズと青い鳥(劇場版)」。
- **C2g 地理澄清**:候选 = 圣地圈按钮(圈名 + 件数 pill)。
- **C3a 集中型搜索**(单圈 ≤50km):点位卡组 top-6 → 地图卡 → AI 总结。
- **C3b 分散型搜索**(≥2 圈/>50km,如《君の名は。》全国):全国概览地图只画圈泡 + 圈卡组,选圈再下钻。
- **C4 search_nearby**:先 LocationPrompt 卡(用途说明 +「位置情報を許可」/「場所を入力する」fallback)。
- **C5 plan_route**:路线卡 → 地图卡带路径 → AI 总结 → 追问 chips。

### SP. 选点工作台(SpotPicker,从「すべて見る」进)
- **SP1 浏览**:返回 + 标题 + 圈内搜索 / 工具条(話数⇄エリア 分组 + 排序 + 「写真あり」filter)/ 左列表 + 右地图。≤300 行直接渲染(单季最重实测 206 点)。
- **SP2 排序**:おすすめ(有图加权,默认)/ 話数順 / 駅から近い順。
- **SP3 选中托盘**:sticky 底部,横向缩略卡 + 步行/距离估算 + 金色「このN件でルートを組む」。
- **SP4 路线顺序**:おまかせ順(最近邻)/ **物語順**(按剧情序,竞品无此!)/ 手動。物語順步行代价超阈值出 warning「物語順だと徒歩 +40分」。
- **SP5 拖拽**:被拖卡抬起 rotate -2.5° + teal 边框,插入位 teal 竖条,托盘序号 ↔ 地图 pin 实时同步。
- **SP8 大规模模式**(>100 点自动切):反转为「编辑草稿」——agent 已选 8 件(每件可「入れ替え」弹邻近候选)+ 名場面 TOP 横滚 + 其余折叠成区域组头(永不平铺)。
- **SP9 锚点委托**:用户标 1–3 个「絶対行く」📌 →「残りはおまかせで埋める」→ agent 围绕锚点补全。把「从 300 选 8」变成「说 2 个必去 + 委托」。

### D. 异常与边界(9 态,都要兜底,永不裸 alt)
D1 作品识别失败(道歉 + 示例 chips,狐狸「うーん、見つからない…」)· D2 0 圣地收录(「まだ Anitabi に登録されていない」+ 相邻推荐)· D3 点位 <3 难成路线 · D4 流中断(inline 重试,**已渲染内容保留**)· D5 超时 60s · D6 校验拒绝(通用道歉,不暴露技术)· D7 地图加载失败(自绘 SVG 兜底 +「地図アプリで開く」)· D8 session 过期(inline 提示,**对话不丢**)· **D9 场景帧 404**(scene-thumb 退化为渐变占位 + 话数文字)。

### E. 交互过程态
- **E1 追问细化 = 活文档更新**:V3 旧路线卡降为过时态(opacity .55 +「以前の版」角标),新卡落底部——**流即历史,不原地改写**;V1 右栏卡原位更新,变更行 nook-yellow flash 1s。
- **E2 勾选重排**(selected_point_ids 旁路):点位卡勾选 → 底部 sticky「5件選択中 ·『ルートを組み直す』」→ 路线卡仅时间轴 skeleton → 足迹行只显「再計算 1.2s」(无管线戏)。
- **E3 站点 ↔ 地图锚定**:hover 站行 ↔ 地图 pin 弹跳放大。
- **E5 地图升格**:静态图「地図を操作 ↗」pill → 角落 spinner → Mapbox GL 无缝接管。

### G. 输入区(正交,贯穿所有层)
G1 默认 pill + 按压影 · G2 聚焦 focus ring(2px `--color-focus`)· G3 有文字才激活发送键(空文字 = muted = 不可按的视觉语义)· **G4 回合运行中:可继续输入,发送键禁用,placeholder「考え中…」,不排队** · G5 发送失败回填文字不让重打。

## 6.5 深入 · Walk 如何逐件打败「四件套」

审判时刻的设计必须精确到「现场用户每一个动作,我们对应哪一块 UI」。下表把创始人现场真用的四件套,逐件映射到 Walk Mode 的对应部件——这是 J9–J14 的施工说明:

| 现场用户在做什么 | 四件套里他开了哪个 | Walk Mode 用什么替代 | 断点 |
|---|---|---|---|
| 「下一站往哪走、还有多远」 | Google Maps 导航 | 「🧭 Mapsで開く」深链(坐标直跳系统地图)+ 下一站行「つぎ → 宇治神社 · 🚶15分 下り」 | J12 |
| 「这个机位的动画长啥样、我站对了吗」 | 翻相册找动画截图 | 当前站卡内嵌 scene-thumb(话数时间戳)+「📷 構図をくらべる」对照子视图 | J10 |
| 「这附近还有别的点吗」 | 开 Anitabi 网页查 | 「📍 近くにあと N スポット」底部 sheet | J11 |
| 「这条路线哪些人走过、有什么坑」 | 翻小红书攻略 | 路线本身来自分享物(已带 ✓ 痕迹与他人实拍),现场不用再查 | J9/J15 |
| 「我走到第几站了、还剩多少」 | 心算 / 反复翻 | 顶部进度条 `●●●○○○○` + 「いまここ 3/7」 | J13 |
| 「记录我来过」 | 拍照 / 心里记 | 「✓ ここに来た!」金色大按钮 → 打卡 → 自动跳下一站 | J13 |

**逐断点施工细节:**

- **J9 现场视图(walk-hero,审判核心)**:当前站置顶放大是整屏的灵魂。大字号站名要在户外强光、单手持机、可能边走边看的条件下一眼可读——这意味着站名字号要比常规移动端标题更大(参考 walk-v0 原型:站名 30px+ 重 900)。场景对照帧紧贴站名下方,让「我要找的画面」和「我现在在哪站」同框。
- **J10 机位对照**:多图分层露出——站(50m 半径,一个点)→ 机位(10m,具体角度)→ カット(单帧)。详情页是折叠 filmstrip(代表帧 ×3 +「+N」),全屏机位浏览器逐帧翻,Walk Mode 当前站展开成「待复刻构图清单」——拍到一张勾一张,勾选数据喂给しおり的完成率。**场景帧 404 必须有正式兜底**(渐变占位 + 话数文字,见 D9),绝不裸 broken image,因为现场没有第二次机会。
- **J11 附近点位**:sheet 从底部滑出(单手够得到),列出半径内其他点(可能跨作品)。数据来自后端 search_nearby(已有,带半径 + LIMIT 封顶),缺的只是这个现场 UI。
- **J12 Maps 深链**:成本极低(一个 `https://maps.../?q=lat,lng` 链接),但不做会被专程吐槽。**不自建导航**——导航是 Google/Apple 的主场,我们只借力。
- **J13 打卡 + 进度**:「✓ ここに来た!」是全屏最大的金色热点,放屏幕下半区单手可按。按下 → 触觉反馈(vibrate)→ 进度条点亮一格 → 下一站自动置顶。全部走完 → 完成屏(狐狸举旗)。打卡存本地(idb),在线时同步;弱网下排队,回网 flush(iOS 无 Background Sync,用 online/visibilitychange 前台 flush)。
- **J14 环境约束**:见 §3.4 约束段。一句话:**这一屏是为「站在太阳底下、信号两格、另一只手拿着包」的人设计的**,任何在桌面舒适环境下看起来"够大够清楚"的尺寸,放到现场都要再放大一档。

## 6.6 深入 · 路线卡(TimedItinerary)完整解剖

路线卡是产品的招牌,也是设计 agent 最常要搭的复杂组件。完整结构(自上而下):

```
┌─ route-eyebrow ──── UJI · HALF-DAY ROUTE          (全大写英文,muted,letter-spacing 宽)
├─ route-title ────── 宇治・半日きらめきルート       (Nunito 900,fg-heading)
├─ route-meta ─────── [ゆったり] 6スポット · 徒歩60分 3.8km · 13:00→16:35
│                      ↑ pacing pill(walk-bg/fg 绿)  ↑ 数量·步行·时间窗
├─ timeline(站粒度 grid:HH:MM | 轨道 | 内容)─────────────
│   13:00  ●  宇治橋 [第1話] · 15分滞在
│          │  🚶 6分 · 平等院表参道、第2話に登場     ← walk 胶囊(绿,独立可见)
│   13:21  ●  平等院 [第3話] · 40分滞在
│          │  🚶 12分
│   …
│   15:00  ★  大吉山展望台 [第8話] · 30分滞在 ★高光   ← 金色 ★ 圆
│              [scene-thumb:第8話 18:30 のカット]    ← 场景对照帧
│   16:35  ●  終点
├─ route-foot ───────────────────────────────────
│   [しおりにして共有]  [Google マップで開く]  [保存する]  [歩くモード(预留)]
│    ↑ 金色主 CTA        ↑ cream             ↑ cream      ↑ 留位
```

**关键设计点:**
- **pacing 三档配色**:ゆったり = walk 绿 / 适中 = explore 橙 / 紧张 = nook-red。让"这条路线累不累"一眼可感。
- **时刻是真的**:HH:MM 不是装饰,是排好的可执行时刻表。13:00 出发、16:35 到——用户能据此买车票。
- **散步段是内容不是间隙**:walk 胶囊带「沿途看什么」(「第2話に登場」),因为走路本身也是巡礼。
- **场景帧入路线卡**:让"时刻表"同时是"画面预告"。
- **V1 双栏特殊形态**:用 `two-col-route` 两列布局(左 3 站 / 右 3 站),吃满右栏宽度;入场依据可显式说明(「大吉山は第8話のベンチ、明るい15:00に入れました」)——让 agent 的排程理由可见,建立信任。

**地图卡 pin 语言**(沿用首页 RouteTrail,全产品一致):
- 起点:teal 实心圆,白字「出」
- 普通站:teal 空心圆(`stroke:#19c8b9 fill:#fff`)+ 白底黑数字
- 高光站:金色实心圆 + ★(`fill:#f0b429`)
- 路径:暖棕虚线(`stroke:#8a6f4d dasharray:2 9 linecap:round`)
- Route 诞生后地图升格:轨迹醒目绘制、pin 按步行顺序重编号、非路线点降透明、**金色路线 pill 常驻地图角落**(直达路线详情 / 歩くモード)

**OG 竖图(9:16,分享物)技术与设计**:satori + resvg-wasm 生成 PNG。封面帧渐变底(代表站场景帧色,如 `linear-gradient(135deg,#5a6e8f,#b87f7a 60%,#e8b87a)`)+ 白字标题阴影 + 打卡清单(时刻+站名+✓)+ 完成率。字体 Noto Sans JP 放 R2。四个工程坑(给实现者):WASM 静态 import、远程图转 base64、只出 PNG、带 UA 头。

## 6.7 深入 · 数据流与工具(generative UI 从哪来)

chat 的每张卡片背后是一个后端工具。设计 agent 理解「哪个工具产出哪种卡」有助于搭对状态:

| 工具 | 干什么 | 产出的 UI |
|---|---|---|
| `resolve_anime` | 作品名 → bangumi_id(API 优先,DB 缓存) | 足迹行第一步「タイトル確認 · Bangumi ✓」;失败 → C2 澄清(同名歧义)/ D1 |
| `search_bangumi` | bangumi_id → 该作所有圣地点位 | 集中型 → C3a 点位卡组;分散型 → C3b 圈总览 |
| `search_nearby` | 坐标 + 半径 → 附近点位 | C4 LocationPrompt → 点位卡;Walk 里的 J11 附近 sheet |
| `plan_route` | 选中点位 → 最近邻排序的路线 | C5 路线卡(TimedItinerary)+ 地图轨迹 |
| `greet_user` / `answer_question` / `clarify` | 问候 / 答疑 / 澄清 | C1 纯气泡 / C2 澄清按钮(永不出管线) |

**旁路输入**(不经 agent,不演 agent 的戏):用户在点位卡勾选 → `selected_point_ids` 旁路 → 直接重排路线(E2,「再計算 1.2s」,只时间轴 skeleton,无管线)。这是「没经过 agent 的事就不演 agent 的戏」原则的来源。

**两周 Walk 子集的建造链**(ADR 决策):ingest CLI/worker(预收录点位)→ 4 个 API(search / spots / routes / bundle)→ 窄入口 agent(失败退普通搜索)→ 前端核心(结果卡 / 选点 / 地图 / Walk Mode)→ しおり 客户端生成。技术栈:TS + Hono + CF Workers、AI SDK v5 + Zod、MapLibre + Protomaps PMTiles on R2、Serwist PWA(scope 仅 Walk 离线壳)。

## 6.8 深入 · 文案与语气(狐狸 コンちゃん + 错误人话)

设计 agent 写 UI 文案时的语气基准。**全产品日文为主**(目标用户日本圈 + 中文圈都看日文 UI),狐狸是叙述者。

**狐狸 コンちゃん(聖地巡礼ガイド)语气**:第一人称、亲切、像一起去玩的朋友,不是客服。
- 问候:「こんにちは!どの作品の聖地へ?」
- 搜索中:「いま Anitabi でさがしてるよ… 8/23」「みつけたら地図にピンを立てていくね🚩」
- 找不到:「うーん、見つからない…」(不说「エラーが発生しました」)
- 完成:「できた〜!🚩 6箇所・歩き60分のゆったりコース」

**错误必须说人话,不暴露技术**:
- 后端不可达:「サーバーに接続できません · 再試行」(不是 500 Internal Error)
- 超时:「時間がかかりすぎているみたい · もう一度」
- 校验拒绝:「うまく言えなかったみたい。言い方を変えてみて」(不暴露 ModelRetry/validator)
- 0 圣地:「この作品はまだ Anitabi に聖地が登録されていないみたい」+ 相邻推荐

**常用日文 UI 字串库**(给 agent 直接取用):
- 操作:聖地を探す / ルートを組む / 保存する / しおりにして共有 / Google マップで開く / すべて見る → / 位置情報を許可 / 場所を入力する

## 6.9 深入 · Phase 2 桌面双栏(V1 工作台)与跨设备交接

V3 单列流是全端基底也是移动端最终形态;桌面 ≥1024px 在环闭合后**升级**为 V1 双栏(同一套 generative UI 组件,registry 不变,只是挂载点从"流里"变成"右栏")。规划是桌面场景,走是手机场景——双栏服务前者,Walk 服务后者,跨设备交接把两者缝起来。

**V1 双栏三幕**(参照 `v1-workbench.html`):
- **ACT 1 空态**:左栏狐狸问候 + 3 枚示例 chips;右栏**虚线框 quiet 态**(「作品をきくと、ここに地図とルートが現れます」)。不用教学浮层,虚线框自己预告右栏用途。体现「UI stays quiet」——右栏空着也安静,不喊。
- **ACT 2 等待态**:左栏管线点亮 + ≥4s 情绪卡;右栏出 **map band skeleton + 3 张卡 skeleton**。注意:**只有视觉工具开跑右栏才出 skeleton**,纯文字回合右栏保持空(F2 只在 B2d 触发)。
- **ACT 3 完成态(招牌画面)**:左栏对话**退为旁白**——足迹一行(「✓ タイトル確認 → 23スポット → ルート作成 9.2s」)+ AI 总结 + anchor link「→ 右のルートを見る」+ 追问 chips;右栏是**海报级路线卡(两列时间轴)+ 完整路线地图**。左读右看,对话和结果同屏互认。

**Phase 2 专属状态(F)**:
- **F1 右栏空(冷启动)**:虚线框 quiet 态。
- **F2 右栏 skeleton**:B2d 的右栏形态(map band + 卡片 skel)。
- **F3 锚定就绪**:AI 气泡含「→ 右のルートを見る」teal 下划线链接;hover 左栏某条消息 → 右栏对应卡片亮起(边框 `--color-primary` 1.5px 光环)。**对话和结果双向互认**是双栏的核心价值。
- **F4 宽度回流**:窗口 <1024px → 右栏组件回流进消息流原位(同组件换挂载点,registry 不变),滚动位置保持当前阅读的消息。移动端降级:底部 tab「チャット / ルート」切换。

**跨设备交接**(参照 `journey-walkthrough-desktop.html` D5d):桌面排好路线 → 「ルートを保存しました🎉」+ **QR 码** + 说明「現地ではスマホの『歩くモード』へ」。这就是登录的真正卖点——不是"保存到云",而是"桌面排的路线,扫码就到手机上,现场打开 Walk Mode"。登录价值 = **跨设备连续性**。

**桌面"内容很多"的三层消化**(参照 desktop walkthrough D3+):右栏先给 ≤6 张精选卡 + GroupToggle 折叠(「1期 42件 ▾ / 2期 78件 ▸ / 3期 70件 ▸ / 劇場版 16件 ▸」)+「すべて見る(206件)→ 聖地を選ぶ」入口 → 进 SpotPicker。**永不一次平铺几百个点**,逐层下钻。

## 7. 分期与登录墙(给排期/取舍用)

**建造顺序**(旅程图对 roadmap 的唯一修正:chat Phase 2 桌面双栏降级到环闭合后,Walk + 分享面插队):

1. **chat Phase 1(V3 单列流)** — 兑现 Plan 段(J6/J7/J8),路线由此可被创建。对着新 TS 后端建。
2. **Walk Mode 最小版(J9–J14)** — 审判时刻优先于桌面增强。先证明「现场那一屏能让用户确认『我到了』」。
3. **share landing + OG 竖图 + 公开作品页** — 一个交付物吃 J1–J5 + J15(发見/判断/Keep 三段同解)。
4. **环闭合后**:chat Phase 2 双栏(V1)、历史路线(J17)、机位模式完整版(J18)、SEO 规模化、同行协作(J16)。

**登录墙(P5)**:
- **免登录**:公开作品页/分享页、chat 看圣地、chat 改路线、选点工作台。
- **登录触发**:只在按「保存する」时弹(magic link)。
- **登录卖点**:「把路线带去旅途」(跨设备连续性),不是「保存」。

## 8. 设计原则与约束(贯穿全程)

- **動森キャンプ 设计系统**:奶油/棕三层底、teal 交互、gold/pumpkin CTA、**3D 按压影**(深度靠影不靠饱和度)、pill 形交互件、Nunito + Zen Maru Gothic。详见 `frontend/DESIGN.md` 与同步进 Claude Design 的 conventions。
- **UI stays quiet, content speaks**:照片和地图出彩,UI 安静。卡片是 cream,不抢动画截图的色。
- **地图 static-first**:默认静态/插画 + SVG 叠加,点击才挂 GL(反 Anitabi 现场卡顿的教训)。静态层**永不画 >50 pin**。
- **没经过 agent 的事不演 agent 的戏**:勾选重排/纯文字回合不出管线 skeleton。
- **活文档,不原地改写历史**:V3 流即历史(旧卡降过时态),V1 面板原位更新 + flash。
- **永不裸 alt / 永不裸错误**:每个加载失败都有插画/渐变兜底,每个异常都有人话文案 + 重试,不暴露技术细节。
- **户外现场是一等公民**:Walk 屏大字、高对比、单手、可离线——这是产品存在的理由。
- **headless 约束**:组件 = headless 逻辑核 + 動森 token 皮;地图性能核写 plain TS(未来回贡献 Anitabi)。
